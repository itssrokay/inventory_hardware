# ADR-008: Display languages and source pictures without changing catalog facts

- Date: 2026-11-06
- Status: Accepted

## Context

The owner requested product images and Hindi/Hinglish modes after the reference catalog release. Translated labels must not become stored selling units, and reference pictures must not overwrite custom shop photos or imply exact variant appearance.

## Decision

Use one shared offline UI dictionary and curated product-term aliases for Android and web. Persist display language separately from speech recognition; preserve canonical fields and original source details. Associate PDF pictures with their own product-table IDs in a separate hash-bound manifest. Copy a source picture into reviewed entry only when no custom photo exists, and show a bundled fallback for older linked products.

**Alternatives considered**

- Translate catalog fields in storage: rejected because identifiers, units and owner-entered names would drift across languages and backups.
- Borrow nearby or web images for unmatched products: rejected because a plausible picture could represent the wrong fitting, material, colour or size.

**Consequences**

- Hindi and Hinglish controls and familiar product names work offline, while original technical source text and custom names remain available. Speech language remains a separate setting.
- 520 matched table pictures cover 2,404 reference variants. Other groups show an explicit missing-picture message; illustrations do not certify size, colour, stock or quantity. Custom photos take priority.
- Display language is an optional preference in existing version 2 backups; reference pictures use existing photo storage and source links, without another Room migration.
