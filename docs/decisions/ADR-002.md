# ADR-002: Use OpenAI only behind explicit review and key boundaries

- Date: 2026-11-06
- Status: Accepted

## Context

Natural Hindi/English entry can misread sizes, prices or selling units, and the user chose OpenAI instead of the provider in the original plan.

## Decision

Use the Responses API with strict JSON schemas. Send parsed items to an editable review and require confirmation before saving. Store phone keys in Android Keystore and keep the localhost development key server-side.

**Alternatives considered**

- Let AI directly update the database: rejected because incorrect prices or dimensions could be silently stored.
- Bundle the development key in the APK or browser JavaScript: rejected because it exposes the credential.

**Consequences**

- Natural entry needs internet and a configured key. Manual entry and local search remain available without either.
